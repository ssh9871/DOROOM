# DOROOM 프로젝트

메인 대시보드, 미니게임 목록, 3D 마이룸을 구현하는 프론트엔드 데모입니다. 현재는 화면 구성과 아바타 이동·점프를 확인할 수 있으며, 모든 동작은 브라우저 안에서 처리합니다.

## 개발 스택

| 구분 | 사용 기술 | 용도 |
|---|---|---|
| 언어 | TypeScript 7.0.2 | 화면 전환, 아바타 조작, 3D 씬 구성 |
| 빌드 | Vite 8.3.4 | Docker 빌드 단계에서 정적 파일 생성 |
| UI | HTML, CSS | 대시보드, 게임 카드, 조작 안내, 확인 팝업 |
| 3D 엔진 | Babylon.js 7.54.3 | 마이룸 렌더링, 카메라, 조명, 그림자 |
| 모델 로더 | @babylonjs/loaders 7.54.3 | GLB 아바타 로딩 |
| 에셋 | GLB, PNG | 3D 캐릭터 및 메인 화면의 정적 미리보기 |
| 빌드 실행 환경 | Node.js 24, npm | 의존성 설치, 테스트, 타입 검사, 빌드 |
| 정적 웹 서버 | nginx | 빌드 결과물 제공 |
| 실행 환경 구성 | Docker, Docker Compose | 환경 설치·빌드·서버 실행 |

별도 UI 프레임워크나 물리 엔진은 사용하지 않습니다. 백엔드·API·DB는 구현하지 않았으며, 사용자명·재화·학습 정보는 고정 예시 값입니다.

## 디렉토리 구성

```text
Doroom/
├─ client/                         # 프론트엔드
│  ├─ index.html                   # HTML 진입점
│  ├─ package.json
│  ├─ package-lock.json
│  ├─ tsconfig.json
│  ├─ src/
│  │  ├─ main.ts                   # 앱 시작점
│  │  ├─ env.d.ts                  # Vite 타입 선언
│  │  ├─ app/app.ts                # 화면 전환·나가기 확인 팝업
│  │  ├─ ui/screens.ts             # 메인·미니게임·마이룸 HTML
│  │  ├─ ui/styles.css             # 화면 스타일 및 반응형 레이아웃
│  │  ├─ room/room.ts              # 3D 방·키 입력·카메라·씬 정리
│  │  ├─ room/model.ts             # GLB 로딩·크기·중심 보정
│  │  ├─ room/movement.ts          # 이동·점프·방 경계 계산
│  │  ├─ room/movement.test.ts     # 이동 계산 검사
│  │  ├─ game/                     # 게임 구현용 빈 경로
│  │  ├─ pets/                     # 펫 구현용 빈 경로
│  │  └─ api/                      # API 연결용 빈 경로
│  ├─ public/assets/
│  │  ├─ avatar/                   # 사용 아바타와 대체 GLB
│  │  ├─ pet/                      # 장식용 대체 고양이 GLB
│  │  └─ previews/                 # 메인 화면용 아바타·펫 PNG
│  └─ tools/                       # GLB 준비·미리보기 생성 도구
├─ server/src/                     # 경로만 준비, 백엔드 코드 없음
│  ├─ routes/
│  ├─ services/
│  ├─ db/
│  └─ middleware/
├─ docs/                           # 검증 기록 및 화면 캡처
├─ Dockerfile                      # Node.js 빌드 → nginx 실행
├─ compose.yaml                    # 웹 컨테이너·로컬 포트 설정
├─ .dockerignore
├─ .gitignore
├─ DOROBUS_펫_탄막게임_데모_개발계획.md
└─ README.md
```

`구현소스/`와 `plan.md`는 로컬 참고 자료로 Git에서 제외합니다. 실행에 필요한 가공된 GLB와 PNG는 `client/public/assets/`에서 관리하므로, 제외된 원본 폴더 없이도 데모를 빌드하고 실행할 수 있습니다.

## 실행 방법

Docker Desktop과 Docker Compose를 준비하고, Docker Desktop의 Linux 컨테이너 엔진을 실행합니다. 호스트에는 Node.js나 npm을 별도로 설치하지 않아도 됩니다.

프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
docker compose up --build -d
```

브라우저에서 [http://localhost:8080](http://localhost:8080)을 엽니다.

Docker 내부의 빌드 과정은 `npm ci → 이동 검사 → 타입 검사 → Vite 빌드` 순서입니다. 실행 시에는 nginx 웹 컨테이너 하나가 빌드된 정적 파일을 제공하며, 별도의 Vite 개발 서버는 실행하지 않습니다. 최초 실행에는 이미지와 패키지를 다운로드할 인터넷 연결이 필요합니다.

```powershell
# 실행 상태 확인
docker compose ps

# 로그 확인
docker compose logs web

# 종료
docker compose down

# 기존 이미지 재실행
docker compose up -d
```

소스를 수정했다면 `docker compose up --build -d`로 다시 빌드하고 브라우저를 새로고침합니다. Docker 실행에는 실시간 소스 반영이 설정되어 있지 않습니다.

로컬 포트는 `127.0.0.1:8080`에만 연결됩니다. 8080 포트가 사용 중이면 `compose.yaml`의 `127.0.0.1:8080:80`에서 호스트 포트를 변경하고 해당 주소로 접속합니다.

실행에 필요한 GLB와 PNG는 이미 포함되어 있어 별도의 에셋 생성 작업도 필요하지 않습니다.

## 구현 진행 상황

| 항목 | 상태 | 현재 동작 |
|---|---|---|
| 실행 환경 | 완료 | Docker 빌드·타입 검사·정적 서버 실행 |
| 메인 대시보드 | 완료 | 예시 디자인 반영, 마이룸·미니게임 이동 |
| 미니게임 목록 | 외관 완료 | 탄막게임 카드 한 개, 플레이하기 비활성 |
| 3D 마이룸 | 기본 구현 완료 | 바닥·벽·조명·그림자·포털 장식·이름표 |
| 아바타 | 기본 구현 완료 | 제공 로봇 GLB 한 개 로딩, 실패 시 대체 GLB 사용 |
| 아바타 조작 | 완료 | WASD 이동, Space 점프, 방향 회전·카메라 추적 |
| 이동 제약 | 완료 | 대각선 속도 제한, 방 경계, 착지, 공중 추가 점프 방지 |
| 마이룸 나가기 | 완료 | 확인 팝업에서 네: 메인 복귀, 아니요·Escape: 유지 |
| 화면 전환 정리 | 완료 | 마이룸 이탈 시 씬·엔진·렌더 루프·입력 이벤트 해제 |
| 펫 | 장식만 구현 | 메인 화면의 정적 미리보기만 사용 |
| 탄막게임 플레이 | 미구현 | 게임 루프·적·탄환·점수·보상 없음 |
| 펫 관리 | 미구현 | 추종·상호작용·뽑기·강화 없음 |
| 백엔드·데이터 저장 | 미구현 | 폴더만 존재, API·DB 연결 없음 |

수업·공작소·계정·재화·학습 차트·프로필·역량 진단·검색·채팅·설정 등은 정적 요소로 표시합니다. 실제 서비스 기능은 연결하지 않았습니다.

### 검증 및 현재 한계

- 이동 계산 검사 6개, 타입 검사, Docker 빌드 통과.
- 실제 브라우저에서 화면 전환·GLB 표시·이동·점프·나가기 팝업 확인.
- 방은 평평한 바닥과 직사각형 경계로 구성하며, 계단·가구 충돌은 지원하지 않습니다.
- 모바일 터치 조작과 다른 기기·브라우저 전체의 호환성은 검증하지 않았습니다.
