### Docker 시작 오류 원인

2026-10-20 12:13:29 KST의 Docker backend 로그에서 Secrets Engine 초기화 중 `engine.sock`을 `engine.sock.stale`로 바꾸는 작업이 “The file cannot be accessed by the system” 오류로 실패했고, 시작 오류 창이 열린 기록을 확인했다. 후속 재시작에서는 Docker Desktop·Docker API·WSL2가 running 상태로 복구됐다. 데이터·볼륨 삭제나 초기화는 수행하지 않았다.

샌드박스 안에서는 별도로 Docker named pipe 및 WSL/로컬 소켓 접근이 거부됐다. 실제 Windows 환경의 승인된 명령 실행으로 엔진 응답과 빌드·HTTP 검증을 완료했다.

### 게임오버 버튼 후속 변경

- 체력 소진 화면 하단에 실제 HTML ‘다시하기’·‘메인으로’ 버튼을 추가했다. 기존 메인 버튼 스타일과 새 판 초기화·내부 메인 복귀 함수를 재사용한다. 게임오버에서는 스킬 버튼을 숨긴다.
- 자동 검사에 체력 0의 게임오버 전환, 재시작 시 체력·점수 초기화, 메인 복귀 시 선택 펫·최고 기록 보존을 추가했다. 전체 검사·타입 검사·Docker 빌드 통과.
- 실제 브라우저에서 체력을 소진해 버튼 표시, 다시하기 클릭 후 새 판 시작, 다시 체력 소진 후 메인으로 클릭 시 게임 창을 유지한 시작 화면 복귀를 확인했다. 콘솔 오류 없음.

### 보스 등장 후 순간이동 수정

- 원인: 골렘은 등장 중 중앙 X좌표를 유지하지만 순찰 전환 시 생성 이후 전체 경과 시간을 사인파에 넣어 약 140px 떨어진 좌표로 즉시 이동했다.
- 등장에 필요한 시간을 제외한 경과 시간으로 순찰 좌표를 계산하고, 도착 프레임의 남은 시간도 반영해 중앙에서 연속적으로 이동하도록 수정했다. 기존 순찰 범위·주기·탄막은 유지한다.
- 회귀 검사가 수정 전 코드에서 실제 실패하는 것을 확인했다. 수정 후 30/60/144 FPS 및 100ms 간격에서 등장 중 중앙 유지, 매 프레임 이동량 상한, 정지 높이·화면 경계, 좌우 전체 왕복 검사를 통과했다.
- 기존 검사·타입 검사·프로덕션 빌드 통과. Docker 8080 서버 재빌드 완료. 이번 수정은 좌표 자동 검사로 검증했으며 실제 플레이에서 보스 등장까지의 화면 확인은 별도로 진행하지 않았다.

## 게임 기능 복구 (2026-10-25)

- 이후 변경에서 `app.ts`가 구형 캔버스 실행 경로를 다시 사용하고 게임 전용 CSS가 제거되어, 남아 있던 `openGame`의 시작/펫 설정/게임오버/스킬 UI가 연결되지 않은 상태였다. 게임 렌더러에도 구형 게이지와 전체 종료 경로가 복원되어 있었다.
- 현재 로컬의 부분 복구와 추가된 리더보드·점수 저장을 유지하면서 `openGame` 진입·정리, 전용 CSS, E 스킬 안내, 바 제거, 일시정지 내부 메인 복귀를 재연결했다. 펫 선택·게임오버 두 버튼·보스 이동 수정은 남아 있던 구현을 재사용한다.
- 기존 62개 검사, 게임/보스 회귀 검사, 새 점수 기록 중복 방지·보존 검사 및 타입 검사·빌드 통과. Docker 8080 서버를 재빌드했다.
- 브라우저에서 시작 화면, 고양이 한 마리의 외견·레벨·경험치·능력, 선택/E 입력 차단, E 스킬·쿨타임·초록 테두리, 일시정지 메인 복귀, 전체 종료·재진입, 게임오버 두 버튼 표시와 메인 복귀, 리더보드 표시를 확인했다. 콘솔 오류 없음.
- 보스 이동은 30/60/144 FPS 및 100ms 간격 자동 검사로 재확인했다. 이번 복구에서 모바일과 장시간 플레이는 재검증하지 않았다. DB 설계와 기존 점수 저장 데이터는 수정하지 않았다.
