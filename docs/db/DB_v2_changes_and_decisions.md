# DB v2 변경 사항 · 팀 확정 필요 목록

> 작성: 양창규 / 11.12 팀장님 최종 답변 기준, 11.13 갱신
> 파일: GitHub `server/src/db/schema_v2.sql`, `seed_and_test_v2.sql` (PostgreSQL 16에서 전체 실행·검증 완료, 26개 테이블 + 뷰 1개)
> 읽는 법: 1~3장은 "왜 바뀌었나", **4장은 확정해야 하는 것을 🟨 전체 / 🟩 도로팜 / 🟥 미니게임으로 나눈 것** — 자기 팀 칸만 보면 되고, 전체 회의는 4장 맨 아래 "회의 안건 3개"만.

## 1. 뺀 테이블 (10개 → 왜 뺐나)

### user_pet_ability (펫 능력 장착 슬롯)
- 중간발표 때는 "펫이 진화하면 능력 칸이 열리고 다른 펫의 능력을 끼운다"는 구조였음
- 팀장님 답변으로 **펫 능력은 종마다 고유 1개 + 장비로 강화**하는 방향이 확정됨
- 능력 장착 칸과 장비 장착 칸이 둘 다 있으면 펫 화면이 복잡해지고, 두 팀이 같은 "슬롯"이라는 말을 다르게 쓰게 됨
- 그래서 고유 능력은 `pet_species.innate_ability_id` 한 컬럼으로 줄이고, 장착 칸은 **장비 슬롯 하나로 통일**

### weekly_ranking_result (주간 랭킹 스냅샷)
- v1은 매주 마감 때 순위를 테이블에 복사해 저장하는 구조였음
- 랭킹이 **무한모드 최고 점수 하나**로 단순해져서, `game_run`에서 주차별 MAX(score)를 뽑는 뷰(`v_weekly_ranking`)로 충분
- 같은 데이터를 두 군데 저장하면 둘이 어긋날 때 어느 쪽이 맞는지 따져야 해서 오히려 위험
- 지난주 순위도 뷰에 `week_start` 조건만 주면 똑같이 나옴

### ranking_reward_tier (순위 구간별 보상표)
- 보상이 **1위 칭호 + 소액 셀**로 정리되면서, "1~3위 / 4~10위 / …" 식의 구간 테이블이 필요 없어짐
- 구간별 셀 금액은 `game_setting`에 3줄(TOP1/TOP3/TOP10)로 넣어 둠 → 바꾸고 싶으면 값만 수정

### pet_skin, user_pet_skin (스킨) — ⚠️ 11/13 크로마 방식으로 재검토 중
- 팀 회의에서 스킨 제외 결정 (3D 모델 추가 제작 부담)
- 11/13: 모델은 그대로 두고 **색만 바꾸는 크로마 방식**이면 제작 부담이 없어서 다시 넣는 쪽으로 검토. 획득 방법이 정해지면 테이블 2개 + user_pet.skin_id 컬럼으로 복귀 (4-8 참고)

### farm, decoration, farm_object, farm_visit_log (농장 4개)
- 처음엔 "동물농장식 육성"을 생각해서 농장 꾸미기·방문 기능을 넣어 뒀었음
- 팀장님 피드백 + 회의에서 **도로팜 = 펫 돌봄 화면**으로 범위를 줄임. 꾸미기·방문은 안 함
- 4개 테이블이 통째로 쓸 데가 없어져서 삭제

### quest, user_quest (퀘스트)
- 퀘스트는 아직 미정 → 미정인 걸 스키마에 남겨 두면 "이거 하는 거야?"가 계속 나와서 일단 제거
- 하기로 하면 v1 설계 그대로 2개 테이블만 다시 추가하면 됨 (다른 테이블에 영향 없음)
- 11/13: 퀘스트 내용·도입 여부는 **미니게임 팀이 개발하면서 결정**. 넣기로 하면 창규에게 알려주면 테이블 추가 (보상 셀은 addCell(reason: QUEST_REWARD)로)

### evolution_rule (옛 진화 규칙)
- v1은 "진화 단계마다 능력 칸이 열린다"는 전제로 만든 테이블이라 능력 슬롯을 빼면 의미가 없음
- 등급(NORMAL/RARE/LEGEND)별로 요구 레벨과 셀 비용이 달라야 해서 `pet_evolution_rule`로 새로 설계

## 2. 새로 넣은 테이블 (11개 → 왜 넣었나)

| 테이블 | 왜 필요한가 |
| --- | --- |
| pet_grade_rule | 등급(NORMAL/RARE/LEGEND)마다 최대 레벨·레벨업 경험치·장비 슬롯 수·전승 비율이 다름. 코드에 숫자를 박지 않고 표로 둬서 밸런스 조정 시 DB 값만 바꾸면 됨 |
| pet_evolution_rule | "레벨은 오르고, 적정 레벨에서 진화" 결정 반영. 등급 × 진화 단계(1→2→3)별 요구 레벨·셀 비용·부활 능력 부여 여부 |
| equipment | 장비 도감. 같은 계열(line_code)이 NORMAL→RARE→LEGEND로 이어지도록 `next_equipment_id`, `merge_count`를 둠 (장비 등급 진화 건의안) |
| user_equipment | 회원이 가진 장비와 수량 (뽑기로 중복 획득 가능하니 수량 컬럼 필요) |
| user_pet_equipment | 펫의 장비 슬롯(1~3번)에 어떤 장비가 끼워져 있는지 |
| stat_upgrade_rule | 쿠키런식 영구 스탯 강화(2안). 스탯 종류 × 레벨별 셀 비용·보너스 값 |
| user_stat_upgrade | 회원별 각 스탯이 몇 레벨인지 |
| pet_exp_transfer | 경험치 전승 기록. "어느 펫 → 어느 펫, 몇 레벨 → 몇 레벨" 남겨 둬야 문의·버그 추적 가능 |
| title | 칭호 목록 (랭킹 1위 보상 등) |
| user_title | 회원이 획득한 칭호. 장착 중인 칭호는 `app_user.equipped_title_id` |
| (gacha_pool.pool_type) | 테이블 추가는 아니지만, 펫 뽑기와 장비 뽑기를 한 테이블에서 구분하는 컬럼 추가 |

## 4. 🔴 확정해야 하는 것 — 담당별

> 아래는 결정이 안 돼서 **내가 임의로 정해 둔 값**임. 대부분 seed(초기 데이터) 값이라 **바꿔도 테이블 구조는 안 바뀜**.
> 🟨 전체 = 두 팀이 같이 정해야 함 (한쪽이 바꾸면 다른 쪽 코드·데이터가 바뀜)
> 🟩 도로팜 내부 / 🟥 미니게임 내부 = 그 팀이 정하고 창규에게 알려주면 됨
> ⚠️ 표시 = **구조가 바뀌는 것** → 코딩 시작 전에 정해야 함. 나머지는 개발하면서 바꿔도 됨.

---

### 🟨 전체 (두 팀 합의)

**A. 펫 기본 능력치 성장 방식 ⚠️**
- [ ] 레벨·진화가 공격력/체력을 어떻게 올리는지 — 임의값 없음 (v2에 빠져 있던 부분)
    - 추천 A: `(등급 기본값 + 레벨 × 레벨당 증가) × 진화 배율` → pet_grade_rule에 base/per_level 컬럼, pet_evolution_rule에 stat_multiplier 추가
    - B: 종마다 다른 성장 (pet_species_stat 테이블, 24종 × 스탯 수 밸런싱 필요)
    - C: 레벨은 능력치 무관, 진화 배율만
    - 전체인 이유: 도로팜이 키운 결과를 미니게임이 getPetCombatStats()로 받아 쓰기 때문

**B. 능력치 코드 공유 ⚠️**
- [ ] 미니게임이 쓰는 능력치 이름(예: ATTACK, MAX_HP, MOVE_SPEED, BULLET_SPEED)을 **하나의 목록**으로 — 펫 기본값·장비·영구 강화가 전부 이 코드를 씀
    - 목록 자체는 🟥 미니게임이 정함 (4-7 참고). 전체 안건인 건 "한 목록을 다 같이 쓴다"는 약속 부분

**C. 셀 경제 (들어오는 양 vs 나가는 양)**
- [ ] 무한모드 셀 보상 — 임의값 `점수 ÷ 100`
- [ ] 스테이지 보상 — 임의값 첫 클리어 100/150/200/300셀, 반복 10/20/30/40셀
- [ ] 주간 랭킹 셀 보상 — 임의값 1위 300 / 2~3위 200 / 4~10위 100 (+1위 칭호) ※ 칭호+셀 지급은 11/13 확정
- [ ] 경험치 보상 — 임의값 `점수 ÷ 10`
    - 전체인 이유: 미니게임이 주는 셀로 도로팜에서 뽑기·강화·진화를 하니까, 한쪽만 바꾸면 밸런스가 깨짐. 뽑기·강화 가격(🟩)과 같이 봐야 함

**D. 출전 조건**
- [ ] 배고픔 기준 — 임의값 30 이상이어야 출전, 전날 돌봄 없으면 00시에 20 감소
    - 전체인 이유: 도로팜 상태가 미니게임 입장을 막는 유일한 지점

**E. 랭킹 마감**
- [ ] 마감 시각 — 임의값 매주 월요일 00:00. 리더보드는 상위 10명 + 내 순위

**F. 도로버스 계정 연동 (팀장님께 확인)**
- [ ] 도로버스에서 우리 메뉴로 들어올 때 학생 식별 정보를 어떤 형태로 받는지 (토큰? 학생 ID?) — 현재 명세서의 회원가입/로그인 API와 app_user.login_id/password_hash는 **개발용 임시**. 연동 방식이 나오면 dorobus_user_id 같은 컬럼으로 교체

### 🟩 도로팜 내부

**펫 성장 수치**
- [ ] 등급별 최대 레벨 — 임의값 NORMAL 30 / RARE 40 / LEGEND 50
- [ ] 레벨업 필요 경험치 — 임의값 `현재 레벨 × 등급 기본값` (NORMAL 100 / RARE 150 / LEGEND 200). 예: NORMAL Lv.5→6은 500
    - 고정값으로 바꾸려면 addPetExp 공식 한 줄만 수정
- [ ] 진화 요구 레벨 / 셀 비용 — 임의값
    | 등급 | 2단계 진화 | 3단계 진화 |
    | --- | --- | --- |
    | NORMAL | Lv.10 / 50셀 | Lv.20 / 100셀 |
    | RARE | Lv.15 / 80셀 | Lv.30 / 150셀 |
    | LEGEND | Lv.20 / 120셀 | Lv.40 / 200셀 |
- [ ] 부활 능력 — 임의값 3단계 진화 시 부활 1회 (게임 중 1번)
- [ ] 경험치 전승 비율 — 임의값 같은 등급 100%, 하위→상위 50%, 상위→하위 불가. 전승 후 보낸 펫은 Lv.1

**장비**
- [ ] 장비 슬롯 해금 기준 ⚠️ — 임의값 **등급으로** (NORMAL 1칸 / RARE 2칸 / LEGEND 3칸)
    - 다른 선택지: 진화 단계로 (1단계 1칸 → 3단계 3칸, **추천**) / 레벨로 (Lv.10/20/30)
    - 바뀌면 equip_slot_count 컬럼 위치만 이동
- [ ] 장비 등급 진화(합치기) 채택 여부 ⚠️ — 건의안: 같은 장비 **3개 + 셀** → 다음 등급 1개
    - 안 하면 next_equipment_id, merge_count, merge_cell_cost 컬럼 + /equipments/merge API 삭제
    - 개별 강화(+1, +2…) 방식은 테이블 구조가 통째로 바뀌므로 **비추천**
- [ ] 슬롯 종류 — 임의값 1=HEAD, 2=BODY, 3=ACCESSORY 고정. 종류 없이 3칸이면 slot_type 컬럼만 삭제
- [ ] 장비 수치 — 임의값 장비 1개당 스탯 1종, 등급별 10 / 20 / 35. 합치기 비용 Normal→Rare 50, Rare→Legend 150
- [ ] 한 장비를 여러 펫에 동시 장착 가능? — 임의값 가능

**영구 스탯 강화 (로비에서 셀로 구매, 뱀서 파워업·쿠키런 강화와 같은 구조)**
- [ ] 적용 범위 — 임의값 **계정 전체** (펫마다 따로면 user_stat_upgrade에 user_pet_id 추가, 전승 시 처리 규칙도 필요)
- [ ] 최대 레벨 / 비용 — 임의값 5레벨, 셀 50 → 100 → 150 → 200 → 250, 보너스 +5씩
- 스탯 목록은 🟥 미니게임이 정함

**뽑기**
- [ ] 펫 뽑기 — 임의값 100셀, 하루 10회, 천장 30회, 중복 시 30셀 환급
- [ ] 장비 뽑기 — 임의값 60셀, 하루 20회, 천장 없음, 중복은 수량 +1
- [ ] 등급별 확률 — 임의값 NORMAL 80% / RARE 17% / LEGEND 3%

**스킨 (크로마)**
- [ ] 도입 여부 — 모델 그대로, 색(텍스처)만 변경. 3D 추가 제작 없음
- [ ] 획득 방법 = 셀 사용처로 할지 — 유력: 셀 구매
    - 셀 구매 → pet_skin, user_pet_skin, user_pet.skin_id 추가 + cell_transaction.reason에 SKIN_PURCHASE
    - 뽑기 → gacha_pool_entry에 skin_id 선택지 / 보상 → reward_mail에 skin_id
- [ ] 종마다 색 몇 개 / 가격

**칭호**
- [ ] 종류 — 임의값 "이번 주 정화 1위", "마지막 동기화 완수"(작전 4 클리어). 더 넣을지?

### 🟥 미니게임 내부

**점수·검증**
- [ ] 점수 공식 — 임의값 `생존 초 × 10 + 처치 수 × 5 + (스테이지 클리어 시 보너스 100/200/400/800)`. 서버(gameService)가 계산, 클라이언트 점수는 안 받음
- [ ] 부정 점수 방지 기준 — 임의값 생존 시간이 서버 기록보다 5초 이상 길거나 초당 처치 20 넘으면 거부
- 셀·경험치 **보상량**은 🟨 C에서 같이 결정

**능력치 목록** (→ 🟨 B)

    - 게임 중 뱀서식 레벨업 선택지는 DB와 무관, 미니게임 코드 안에서만

**게임 중 버프·부활**
- [ ] GAME_BUFF 아이템 효과 (effect_config JSON에 무엇을 담을지) — 임의값 없음
- [ ] 부활 1회의 게임 내 처리 방식
